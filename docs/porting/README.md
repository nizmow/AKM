# Atari porting guide

- [Roadmap](../ROADMAP.md): project goals, phase boundaries, and release criteria.
- [GitHub issues](https://github.com/nizmow/AKM/issues): remaining work, prerequisites and completion criteria. Keep actionable backlog there rather than in a second repository checklist.
- [Build catalogue](APPLICATION_BUILDS.md): component inventory, what builds, and what has actually run. An untested runtime path is not proof of missing code. Historical `MagiC/...` paths there are pre-retirement locations, browsable through the [historical snapshot](../../README.md#historical-source-tree).
- [Porting workflow and pitfalls](WORKFLOW.md): what to check before changing a port, and which tools to reuse.
- [Porting notes](PORTING_NOTES.md): component-specific ABI, encoding, packaging, and verification details.
- [Automated testing](TESTING.md), [hardware testing](MANUAL_TESTING.md), and [NeoST host contract](NeoST_HOST.md): commands, fixture requirements, and coverage limits.

Run command examples from the repository root unless noted. See the [root README](../../README.md) for toolchain setup.
